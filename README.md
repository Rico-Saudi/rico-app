# 🟢 ريكو (Rico)

مساعد عربي بالشات: يفهم طلب المستخدم بلهجته، يدلّه على المحل أو صاحب المهنة
المناسب قرب موقعه، ويأخذ منه الطلب ويوصّله للمحل.

النسخة الأردنية من نفس الكود تُسمّى **تدلل**، وتختلف عن السعودية براية بناء
فقط — لا فرع ولا ملفات موازية (انظر «نسخة لكل سوق» أدناه).

> ريكو لا يوصّل ولا يحصّل بنفسه: يوصل الطلب للمحل، والمحل يكمل مع العميل.

## 📐 من ماذا يتكوّن

| | |
|---|---|
| `lib/` | تطبيق Flutter (أندرويد/iOS) — الشات، الطلبات، حساب العميل، بطاقات أصحاب المهن |
| `server/rico-backend/` | خادم NestJS + MongoDB: التصنيف، البحث، الطلبات، لوحات التحكم، التقارير |
| `server/rico-backend/client/` | لوحتا التحكم (React/Vite): لوحة المحل ولوحة المالك، يخدمهما الخادم نفسه |
| `test/` + `server/rico-backend/src/**/*.spec.ts` | ٨٧٤ اختباراً، تشتغل على كل push (`.github/workflows/ci.yml`) |

كل اتصال بالخارج يمرّ من الخادم: **لا مفاتيح API داخل التطبيق إطلاقاً.**

## 🧠 كيف يفهم الطلب

1. المستخدم يكتب أو يتكلّم («وين أرخص جبنة؟»، «أبغى سبّاك»، «أكّد الطلب»)
2. الصوت → `/transcribe` (Groq Whisper) → نص
3. النص → `/classify`: يصنّفه نموذج لغوي عبر Groq إلى نية ومكان ومنتجات
   وكمية ومزاج. يفشل النموذج أو يتأخر → يسقط التطبيق لمصنّف الكلمات
   المفتاحية المحلي (`lib/services/intent_service.dart`) فلا يبقى بلا جواب
4. النية → بحث: نشاطاتنا الحقيقية في قاعدة البيانات أولاً، ثم Google Places
   لتغطية النقص، ثم عروض الإنترنت عبر Serper
5. `/compose` يصيغ ردّ ريكو بلهجة السوق، وكل ردّ ينتهي بدفع العميل للطلب

## ✨ ما يقدر عليه

**للعميل:** بحث عن أماكن ومهن · مقارنة سعر منتج بين المحلات القريبة · عروض
وأسعار من الإنترنت · طلب من محل مع سلّة ومحادثة متابعة (تعديل، حذف، تأكيد) ·
سجلّ طلبات · مفضّلة · اتصال مباشر من الشات · اقتراحات بحسب الطقس · حساب
بـ OTP

**للمحل:** لوحة تحكم لكل قطاع · منتجات واستيراد CSV · مراحل الطلب وإحصاءاته ·
إيقاف الطلبات مؤقتاً · تنبيه بكل طلب جديد

**للمالك:** نشاطات ومحلات ومطالبات · تحليلات وفجوات بحث · «تعليم ريكو» (كتابة
جواب ريكو يدوياً) · حدود استهلاك واجهات مدفوعة

## 🛠️ التشغيل

### الخادم

```bash
cd server/rico-backend
cp .env.example .env     # ثم املأ المفاتيح: MONGODB_URI، SESSION_SECRET، GROQ_API_KEY …
npm install
npm run seed             # بيانات أولية (اختياري)
npm run start:dev        # على :3000
```

`SESSION_SECRET` إلزامي: الخادم يرفض الإقلاع بدونه عند `NODE_ENV=production`.

### التطبيق

```bash
flutter pub get
flutter run                                        # على الخادم المنشور
flutter run --dart-define=RICO_API=http://localhost:3000    # iOS Simulator / سطح المكتب
flutter run --dart-define=RICO_API=http://10.0.2.2:3000     # محاكي أندرويد
```

### الاختبارات

```bash
flutter analyze && flutter test
cd server/rico-backend && npx tsc --noEmit && npx jest
```

## 🌍 نسخة لكل سوق

الفرق بين النسخة السعودية والأردنية رايتا بناء، لا فرعان:

| | السعودية (ريكو) | الأردن (تدلل) |
|---|---|---|
| `RICO_BRAND` | `rico` (الافتراضي) | `tadallal` |
| `RICO_API` | `https://app.rico-go.com` | خادم الأردن |

```bash
flutter build apk \
  --dart-define=RICO_BRAND=tadallal \
  --dart-define=RICO_API=https://app.tadallal.com
```

الخادم يقرأ `brand` من كل نداء، ومنه يعرف باسم مَن يردّ، وبأي لهجة، وفي أي
بلد يبحث وبأي عملة. الاسم المعروض يملكه الخادم لا التطبيق، فإضافة سوق جديد
ما تحتاج إصدار تطبيق جديد للأسواق القديمة. انظر [lib/brand.dart](lib/brand.dart).

**كل ميزة تُكتب مرة واحدة وتعمل في السوقين.** ما يختلف بينهما بيانات وإعداد
(لهجة، عملة، بلد البحث، المحلات) لا كود — فأي ميزة في فرع سوق واحد عيبٌ
يُصلح، لا تصميم.
